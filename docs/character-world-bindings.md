# 角色与世界书资源

Agent RP 将 SillyTavern 角色卡视为交换格式，而不是内部资源所有权模型。导入带有 `character_book` 的 PNG、JSON 或 CHARX 时，Host 保留原始角色卡字节，同时生成一个独立 World Info 资产和一条角色世界绑定。

## 持久资源

- 角色资产保存在角色库中，内容寻址编号以 `card-` 开头。原始文件始终可以原样读取。
- World Info 资产保存在世界书库中，内容寻址编号以 `world-info-` 开头。两张角色卡带有相同世界书内容时复用同一个资产。
- 角色世界绑定单独保存。主世界与附加世界分别记录来源；从角色卡拆出的主世界标记为 `embedded-import`，`user-bound` 来源值留给后续绑定编辑接口。

无内置世界书的角色也会保存一条主世界为空的绑定记录。该记录表示角色已经迁移，避免 Host 在每次启动时重复解析旧资产。

## 导入与迁移

新的角色导入通过角色库统一完成拆分。Host 启动时只处理没有绑定记录的旧角色，保留原始文件和角色编号。拆出的 World Info JSON 保留角色卡世界书及条目的未知字段，并补充 SillyTavern 独立世界书所需的字段名。

世界书仍被角色绑定时不能从世界书库删除。永久删除已收纳角色会移除绑定，但不会自动删除独立 World 资产；仍需要的世界不会因角色生命周期而消失。

## Session 与导出

当前阶段继续在角色 Session 快照中保留导入卡片的内置世界书，以维持 MVU、世界召回和现有导出路径。启动器会排除同一角色已经绑定的 World，防止用户把拆出的世界书再次选为附加世界后重复注入。

下一阶段以绑定 World 快照替代角色快照中的内置世界书。届时 MVU 从 Session 的有效 World 集合读取初始化和更新规则；“导出当前版本”把绑定的主世界转换回 `data.character_book`，而“导出原始文件”继续返回未修改的导入字节。完成这两项迁移后，运行时不再直接读取 `card.lorebook`。
